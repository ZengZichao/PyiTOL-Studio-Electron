## 1. 结论摘要

PyiTOL Studio 的界面**并不是"审美不好看"的问题，而是设计系统在编译期整体失效、桌面平台适配缺失、关键交互存在功能性缺陷**。三者的叠加，导致界面呈现为一个"在 Electron 里打开的、没有内边距的网页"，而不是一个 macOS 科研数据工具。

### 1.1 五个最关键的结论

| #   | 结论                                                                           | 严重度 | 一句话证据                                                                                                                                          |
| --- | ------------------------------------------------------------------------------ | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **整套间距系统从未生效**：29 个间距类名、190 处使用，编译后 CSS 中一个都不存在 | P0     | `--space-*` 写进了 `:root`，但 Tailwind 只识别 `--spacing-*` 命名空间；构建产物中无 `.p-sm` / `.px-sm` / `.gap-xs`                                  |
| 2   | **macOS 标题栏与工具栏重叠，窗口无法拖动**                                     | P0     | `titleBarStyle: 'hiddenInset'` + `trafficLightPosition {x:16,y:16}`，工具栏第一个按钮从 x≈0 开始，且全项目无 `-webkit-app-region`                   |
| 3   | **四个菜单命令会触发无限递归**                                                 | P0     | `generate-preview` / `export-template` / `import-template` / `show-about` 在 `useMenuCommands` 中被再次派发为同名 `menu-command` 事件，形成同步递归 |
| 4   | **三个面板的分隔条拖拽实际不可用**                                             | P0     | `Splitter` 在 `mousedown` 时闭包捕获了旧的 `onResize`，每次增量都加在拖拽起点的旧宽度上，面板只会微动                                               |
| 5   | **存在多条无保护的数据丢失路径**                                               | P0     | `isDirty` 从未被 UI 消费、关闭窗口无拦截、删除单元/清空数据/整表粘贴均无确认与撤销                                                                  |

### 1.2 其余高频问题（P1）

- 深色主题下 `.btn-utility` 为**白底白字**（对比度 1.00:1），且 `--color-surface-chip` 未在 `.dark` 中定义。
- 浅色主题下 `text-ink-subtle`（#7a7a7a）在羊皮纸底色上仅 **3.94:1**，却被大量用于 12px 说明文字；深色主题品牌蓝 #2e5cff 在 #1d1d1f 上仅 **3.28:1**。
- **渲染层 DOM 的 ARIA 覆盖为 0**：无 `role="dialog"`、无焦点陷阱、无 `aria-live`、表单标签无 `htmlFor`、颜色是状态列唯一信息载体。
- **12px 字号的 `--text-fine-print` 行高被定义为 1.0**，中英文都会被裁切。
- 主数据表宣称"虚拟化"，实际是 `rows.slice(0, 10000)` 全量渲染；`@tanstack/react-virtual` 与 `@tanstack/react-table` 装了但从未使用。
- 向导的类型搜索框把 `Promise` 写进 `types` 状态，清空输入即触发 `types.filter is not a function`，且无 Error Boundary，直接白屏。
- 上传对话框把 API Key 明文写入 `/tmp/pyitol_api_key.txt` 且不删除，界面文案却写"never stored"。
- 原生菜单全英文，与可切换中文的界面不一致；`<html lang>` 永远是 `en`。

### 1.3 做得好的部分（应保留）

- 令牌优先的架构意图清晰：亮/暗双主题、品牌色、字阶、圆角、间距都被显式建模，且注释中写明了设计来源与禁令。
- 图标体系统一使用 `lucide-react`，线宽与语义基本一致。
- 核心流程的 i18n 键覆盖率高（674 行词条），支持运行时热切换。
- 产品思路专业：叶节点 ID 校验、模板语法高亮、"向导 + 检查器 + 数据表 + 预览"的四区布局、命令面板、快捷键，都是科研工具的正确骨架。
- Electron 安全基线到位：`contextIsolation` / `sandbox` / `nodeIntegration: false` / CSP / 外链外开。

**总体判断：骨架是专业的，皮肤是失效的，细节是未经桌面场景验证的。**

1. **源码静态走查**：逐组件检查布局、状态、交互、文案、键盘路径。

4. **平台约定核对**：对照 macOS HIG 与 Electron `titleBarStyle` / 菜单 / accelerator 行为。
5. **状态矩阵推演**：对每个主要界面推演 空 / 载入 / 错误 / 部分成功 / 危险操作 五种状态。

## 3. P0 阻断级问题（必须优先处理）

### LAY-01 间距系统整体失效（29 个类名 / 190 处使用 / 0 个生成）

**现象**

`globals.css:163-170` 定义了：

```
--space-xxs / --space-xs / --space-sm / --space-md / --space-lg / --space-xl / --space-xxl / --space-section
```

但 Tailwind v4 的间距命名空间是 `--spacing-*`（默认 `--spacing: 0.25rem`）。`--space-*` 不属于任何被 Tailwind 识别的命名空间，因此 `p-sm`、`px-sm`、`py-xs`、`gap-xs`、`mt-xxs`、`mb-lg` 等**全部不会被生成**。

**证据**

```bash
# 源码中使用
grep -o "\.p-sm{" out/renderer/assets/index-1_xhN5jD.css   # 无输出
grep -o -- "--spacing-sm" out/renderer/assets/index-1_xhN5jD.css  # 无输出
```

静态统计（从 `className` 提取 → 在构建 CSS 中反查）：

| 类名                      |  使用次数 | 是否生成 |
| ------------------------- | --------: | -------- |
| `gap-xs`                  |        35 | 否       |
| `px-sm`                   |        25 | 否       |
| `py-xs`                   |        20 | 否       |
| `gap-xxs`                 |        15 | 否       |
| `mb-sm`                   |        11 | 否       |
| `mb-xs`                   |        10 | 否       |
| `mt-xxs`                  |         9 | 否       |
| `mt-xs` / `p-sm` / `p-lg` | 7 / 7 / 7 | 否       |
| 其余 19 个                |     共 44 | 否       |

合计 **29 个间距类名、190 处使用，全部未生成**。另有 `bottom-sm`、`right-sm` 也缺失（见 7.8 更新提示）。

**具体后果（全部可在界面上直接看到）**

- 工具栏 `px-sm` 失效 → 左右内边距为 0，第一个按钮贴住窗口左缘。
- 面板 `p-sm` 失效 → 树卡、检查器、表格、预览全部贴边。
- 对话框 `px-lg py-sm` 失效 → 标题与底部按钮紧贴卡片边缘。
- 表格单元格 `px-sm py-xs` 失效 → 文本与列边界零间距，数字列挤在一起。
- 所有 `gap-*` 失效 → 图标与文字、工具栏按钮之间、按钮组内部全部无间隔。
- 欢迎页 `mt-xxl` / `gap-lg` 失效 → 三个入口卡片相互贴住，"最近工程"紧贴主视觉。
- 命令面板 `pt-xxl` 失效 → 浮层贴住窗口顶边，而不是设计意图中的 48px 下沉。

**为什么它最严重**

这不是"某处少写了一个 padding"，而是**所有界面的空间关系同时归零**。任何后续的配色、圆角、阴影优化都会被这个底层失效掩盖。

**建议**

- 将间距令牌改为 Tailwind 可识别命名空间（`@theme { --spacing-xs: ... }`），或改用任意值语法。
- 在 CI 中增加"使用类名 ⊆ 生成类名"的校验，防止再次静默丢失。
- 建立 4/8 栅格：4、8、12、16、24、32、48；不要保留 17px 这种破坏节奏的值。

### MAC-01 红绿灯压住工具栏，且窗口无法拖动

**现象**

- `src/main/index.ts:47-48`：

```ts
titleBarStyle: 'hiddenInset',
trafficLightPosition: { x: 16, y: 16 },
```

- 工具栏高度 44px（`Workbench.tsx:329-332`），在 `px-sm` 失效后第一个按钮从 x=0 开始（`Workbench.tsx:334`）。
- macOS 红绿灯占据约 x=16–72、y=16–30 的区域，与左上角"显示/收起左栏"按钮**直接重叠**。
- 全项目检索 `app-region` / `WebkitAppRegion`：**0 处**。`hiddenInset` 隐藏了原生标题栏，但没有声明任何 drag region，因此 44px 工具栏不能拖动窗口。

**后果**

- 视觉上：窗口左上角出现"按钮上叠按钮"的错位，是用户对应用专业度的第一印象。
- 功能上：用户几乎无法移动窗口（只能依赖系统 Mission Control 等外部手段）。

**建议**

- 工具栏左侧预留 ≥ 80px 的 traffic-light 安全区（`padding-left: 88px`），或把品牌/标题放在该区。
- 给工具栏空白处声明 `-webkit-app-region: drag`，并给所有可点击元素声明 `no-drag`。
- 红绿灯位置与 44px 栏高对齐（垂直居中，通常 y≈15–16，但 x 需与内容避让一起设计）。

### FLW-01 菜单命令无限递归（⌘R / ⌘E / 导入 / 关于）

**现象**

`src/renderer/src/hooks/useMenuCommands.ts:94-100`：

```ts
case 'generate-preview':
case 'export-template':
case 'import-template':
case 'show-about':
  window.dispatchEvent(new CustomEvent('menu-command', { detail: command }))
  break
```

同一文件 `:108-114` 又注册了：

```ts
window.addEventListener('menu-command', windowHandler)
```

`windowHandler` 会把 detail 再交给 `handleCommand`。于是：

`menu:command` → `handleCommand` → `dispatchEvent('menu-command')` → `windowHandler` → `handleCommand` → … 同步递归。

**触发路径**

- 菜单 `Command > Generate Preview`（`Cmd+R`，`menu.ts:123`）
- 菜单 `Command > Export Current Template…`（`Cmd+E`，`menu.ts:124`）
- 菜单 `File > Import Template…`（`Cmd+I`，`menu.ts:31`）
- 菜单 `Help > About`（`menu.ts:135`）
- 命令面板中的"生成预览 / 导出当前模板"项（`CommandPalette.tsx:80-81`）

**后果**

主进程发来的这几个命令会导致渲染进程栈溢出/假死；用户表现为"点了菜单就卡住"。

**建议**

- 事件只用于"跨组件通知"，不能让 IPC 入口与 window 事件互相转发同一命令。
- 为 renderer 建立单一命令总线：IPC → store action，或 window event → store action，二者不互相回环。
- 同时补齐 `import-template` 与 `show-about` 的实际 UI（目前既无导入对话框也无关于面板）。

### FLW-02 向导类型搜索导致白屏

**现象**

`WizardDialog.tsx:291-299`：

```tsx
onChange={(e) => {
  const q = e.target.value.toLowerCase()
  const filtered = types.filter(...)
  setTypes(types.length > 0
    ? (e.target.value ? filtered : window.pyitol.sidecar.call('list_template_types', {})) as TemplateTypeInfo[]
    : types)
}}
```

**问题链**

1. 输入框不是受控组件（没有 `value`）。
2. 清空输入时，`e.target.value` 为假 → 把 `sidecar.call(...)` 返回的 **Promise** 赋给 `types`。
3. 下一次渲染执行 `types.filter(...)`（`:307`）→ `TypeError: types.filter is not a function`。
4. `main.tsx` 没有 Error Boundary → React 卸载整棵树 → **白屏**。
5. 即使不崩溃，每次输入都是在"上一次过滤结果"上继续过滤，退格无法恢复全集。

**建议**

- 受控输入 + 独立 `query` 状态；过滤始终基于完整 `allTypes`。
- 增加 Error Boundary（至少包住三个对话框），并提供"重新加载界面"。
- 搜索框加清空按钮与空结果状态。

### CMP-01 分隔条拖拽失效（闭包捕获旧宽度）

**现象**

`Splitter.tsx:17-45` 在 `mousedown` 时创建 `onMove`，其中调用的是**当时闭包里的 `onResize`**。而 `Workbench.tsx:239-242` 传入的是：

```tsx
onResize={(delta) => setLeftRailWidth(leftRailWidth + delta)}
```

`leftRailWidth` 是拖拽开始那一刻的常量。`startPos` 每次移动都更新，所以 `delta` 是**增量**；把增量加到旧起点上，结果是：

```
最终宽度 ≈ W0 + 最后一次移动的增量
```

而不是 `W0 + 总位移`。用户拖 100px，面板只动几像素，随后"粘住"。

同样的模式出现在：

- 左栏：`Workbench.tsx:239-242`
- 检查器：`Workbench.tsx:274-277`
- 上下分栏：`Workbench.tsx:252-258`

**后果**

三栏布局的尺寸调节实际上不可用，而这正是桌面工作台的核心交互之一。

**建议**

- 拖拽开始时记录 `startWidth`，移动时用 `startWidth + (currentX - startX)` 计算绝对宽度。
- 用 `pointerdown/pointermove/pointerup` + `setPointerCapture`，避免鼠标移出窗口丢失事件。
- 增加键盘可调节（`role="separator"` + 方向键）与双击复位。

### FLW-03 多条无保护的数据丢失路径

| 路径         | 位置                       | 现状                                           |

## 4. 布局与空间系统

### 4.1 令牌命名空间错位（根因）

| 令牌类别 | 定义位置                                             | Tailwind 期望              | 结果                                                                                  |
| -------- | ---------------------------------------------------- | -------------------------- | ------------------------------------------------------------------------------------- |
| 间距     | `--space-*`（`globals.css:163`）                     | `--spacing-*`              | 全部间距类不生成                                                                      |
| 字号     | `--text-body` 等（`globals.css:91-151`，在 `:root`） | `@theme` 内的 `--text-*`   | `text-body` / `text-caption` 等类不存在，只能写内联 `fontSize`                        |
| 圆角     | `--radius-*`（`globals.css:153-160`，在 `:root`）    | `@theme` 内的 `--radius-*` | `rounded-sm/md/lg` 回落 Tailwind 默认值（4/6/8px），与令牌的 8/11/18px **同名不同值** |

### 4.4 最小窗口下的布局

`minWidth: 900`（`main/index.ts:44`）。在 900px 时：

```
左栏 280 + 分隔条 5 + 检查器 360 + 分隔条 5 = 650
中间数据区剩余 250px
```

250px 要容纳"# / 状态 / N 个数据列"，表格基本不可用。设计上应定义：

- < 1100px 自动折叠检查器；
- < 980px 自动折叠左栏；
- 面板折叠后提供明显的恢复入口（当前只有工具栏图标）。
- 不建议用 `md:` 响应式断点（`WizardDialog.tsx:263`），因为桌面窗口宽度与"设备断点"不是同一概念；应使用容器查询或 JS 宽度观察。

### 4.5 触控目标与桌面目标的错配

44px 的按钮在鼠标场景下**过大**，在触屏场景下才合理。桌面端更关键的是：

- 水平方向的"按钮组内间距"与"分组间隔"要有层级差；
- 图标按钮 24–28px 即可，但需要 hover 背景与 tooltip；
- 输入框 28–32px 即可，表格内联编辑 22–24px。

当前用 44px 统一所有控件，再用内联 `minHeight: 26/28/32/38` 局部打补丁，造成"同一界面七种高度"。

## 5. 设计令牌与主题系统

### 5.1 TKN-01 `@theme` 自引用与重复定义

`globals.css:7-23`：

```css
@theme {
  --color-canvas: var(--color-canvas);
  --color-parchment: var(--color-canvas-parchment);
  ...
}
```

构建产物中确实出现三条同名声明的序列：

```css
--color-canvas: var(--color-canvas); /* @theme，位于 layer theme */
--color-canvas: #fff; /* :root，未分层 */
--color-canvas: #1d1d1f; /* .dark，未分层 */
```

**当前能工作，但属于"偶然正确"**：因为未分层样式优先于 `@layer theme`，后两条覆盖了自引用。一旦有人"清理重复定义"，`bg-canvas` 立刻变成无效值。这是典型的设计系统地雷。

**同族问题**：`--color-ink-muted: var(--color-ink-muted-80)` 也是"别名指向别名"，链条越长越脆弱。

**建议**：`@theme` 里只放真实值或只放别名（二选一），不要在 `:root` 再定义同名变量；建立令牌 lint（禁止 `--x: var(--x)`）。

## 6. 视觉层次、密度与品牌语言

### 6.1 设计来源与产品形态错配

`globals.css:26-37` 明确写道：设计系统来自 Apple 营销页规范（`DESIGN.md`），并列出"桌面工具密度：caption(14px) + 等宽数据字体"。但实际根字号是 **17px**（`globals.css:244`），按钮是 **44px 触屏规格**，卡片圆角 **18px**，主按钮 **全圆角胶囊**。

这套语言适合：

- 产品官网、购买页、品牌发布页；
- 低频、以浏览为主的界面。

不适合：

- 高频、以键盘和数据编辑为主的科研工作台；
- 需要与 Finder / Preview / VS Code / RStudio 并排使用的桌面工具。

**视觉后果**："网页感"强于"应用感"：大字号、大留白、大圆角、胶囊按钮、缺少紧凑表格与工具条语言。

### 6.2 层次与留白

- 因为间距归零，层级只能靠字号与边框区分；而主体字号只有 12/14/17 三档（10 与 21 仅局部出现），缺少 11/13 这样的中间档，导致"标题不够重、正文不够轻"。
- 卡片边框 #e0e0e0（1.32:1）与背景几乎融合，卡片边界只能靠阴影，而阴影又只出现在两个浮层里。
- 全站几乎没有"分组容器"（section/panel）概念：工具栏、表格头、检查器分组都是裸元素直接堆叠。

### 6.3 圆角、边框与形状

| 元素              | 圆角                 | 问题                                                                  |
| ----------------- | -------------------- | --------------------------------------------------------------------- |
| `.card`           | 18px                 | 对话框、右键菜单、Toast 全用它；32px 高的菜单项配 18px 外框，比例失调 |
| `.btn-primary`    | 9999px               | 胶囊按钮，与 11px 的次按钮并置时形状语言冲突                          |
| `.btn-pearl`      | 11px                 | 第三种形状                                                            |
| `input-field`     | 8px                  | 第四种                                                                |
| `rounded-sm` 横幅 | 4px（Tailwind 默认） | 第五种，且与令牌 `--radius-sm: 8px` 同名不同值                        |

### 6.4 图标

- 尺寸混用：11 / 12 / 13 / 14 / 16 / 18 / 24 / 28。
- 14px 图标使用默认 `strokeWidth=2`，在 12px 文字旁显得过重；工具栏 14px 图标在 44px 按钮中过小。
- 图标按钮无 hover 底色，只有 `title` 原生 tooltip（延迟约 1s），发现成本高。
- 部分图标承担"状态"（如 ⚠ 文本符号）而非矢量图标，跨平台字体渲染不一致。

### 6.5 欢迎页

- 结构是营销式 hero：64px 标志 → 34px 标题 → 17px 副标题 → 三张 240×140 卡片 → 最近工程。
- 问题：
  - 最近工程被放在 `mt-xxl`（失效后紧贴）下方，权重低于三张"新建"卡；对回访用户，最近工程才是主路径。
  - 没有"返回欢迎页"的入口：进入工作台后无法回到该页。
  - 卡片只有 `active:scale-95`，无 hover 抬升/描边，鼠标用户得不到反馈。
  - 拖拽提示文案承诺"拖入即可开始"，实际拖放只是打开文件选择器（见 FLW-05）。
  - 语言默认 `en`（`i18n/index.ts:667`），中文用户首次启动看到英文首屏。

### 6.6 语法高亮配色

| 类                | 亮色           | 深色           | 问题                               |
| ----------------- | -------------- | -------------- | ---------------------------------- |
| `.hl-header`      | 品牌蓝         | 品牌蓝 #2e5cff | 深色 3.28:1，12px 不达标           |
| `.hl-section`     | #e8590c        | #e8590c        | 亮色 3.58、深色卡片 4.00，均不达标 |

## 7. 组件与模式一致性

### 7.1 按钮：定义了 4 种，用了 2 种，全都没有 hover

### 9.4 文本选择

`globals.css:251` 对 `html, body` 设置 `user-select: none`，且没有为数据区域恢复 `user-select: text`。

- 用户无法复制叶节点 ID、表格单元格、预览代码片段、错误信息。
- 表格单元格却设置了 `cursor: text`（`Workbench.tsx:768`），**光标暗示可选，实际不可选**。
- 只能通过"复制全部预览"按钮复制整段，无法局部复制。

### 9.5 动效

- 全站无 `prefers-reduced-motion` 适配。
- 视图切换有 250ms 整页缩放（`App.tsx:117-135`），对话框有 200ms 缩放，按钮有 active 缩放。
- 对前庭敏感用户不友好；也拖慢高频切换。
- 动画曲线不统一：CSS `0.15s ease`、Framer 默认 spring/ease、`0.2s`、`0.25s` 混用。

### 9.6 语言与读屏

- `<html lang="en">` 固定（`index.html:2`），切换到中文后不更新。
- 中文文本会被英文语音引擎朗读；也影响字体回退与断行。
- 数字/单位无 `lang` 标注（如 `Å`、`px`）。
- 中文与英文混排时使用负字距（全局 `-0.374px`），CJK 字形会被挤压。

### 9.7 其他

- 无跳过导航/地标（`main` / `nav` / `aside`）。
- 无 `prefers-contrast` / `forced-colors` 适配。
- 焦点环 `outline-offset: 2px` 在 `overflow: auto` 容器内会被裁切（表格、检查器、列表）。
- 图标状态（⚠）使用文本符号，读屏会读"警告"但颜色语义缺失。

## 10. macOS / Electron 桌面适配

### 10.1 Electron 在 macOS 上的"原生感"取舍

Electron 使用 Chromium 渲染，天然更接近"网页"而不是 AppKit。弥补方式不是去模仿像素，而是采用平台惯例：

- 原生红绿灯 + 显式 drag region + 与栏高对齐的安全区；
- 28–32px 的工具条与控件、13px 基准字号、系统字体；
- 原生菜单、系统强调色、系统滚动条与选择色、`color-scheme`；
- 文档窗口语义：标题显示文件名与脏状态、最近文件、恢复、偏好设置（⌘,）。

当前实现恰好相反：**窗口 chrome 没有适配平台，内容区却使用了营销页的字号与胶囊按钮**——同时失去了"原生感"与"网页精致感"。

### 10.2 作为 Workbench 桌面原型的基线核对

按 Stark 的桌面原型分类，本产品属于 **Workbench**：文档窗口 + 工具栏 + 侧栏 + 主工作区 + 检查器，强调稳定工具栏、键盘优先、文档状态可见、布局持久化。逐项核对：

| 基线能力                         | 现状                                                 | 结论 |
| -------------------------------- | ---------------------------------------------------- | ---- |
| 文档窗口语义                     | 单窗口可用，但标题不反映文档                         | 部分 |

## 15. 设计系统建议（目标态）

### 15.1 桌面密度令牌（建议值）

| 类别     | 令牌                                       | 建议值                                                       |
| -------- | ------------------------------------------ | ------------------------------------------------------------ |
| 字号     | `--text-2xs` / `xs` / `sm` / `base` / `lg` | 10 / 11 / 12 / 13 / 15                                       |
| 行高     | 对应                                       | 1.4 / 1.45 / 1.5 / 1.5 / 1.4                                 |
| 控件高度 | `--control-sm/md/lg`                       | 24 / 28 / 32                                                 |
| 间距     | `--spacing-1..6`                           | 4 / 8 / 12 / 16 / 24 / 32                                    |
| 圆角     | `--radius-xs/sm/md/lg`                     | 4 / 6 / 8 / 10                                               |
| 边框     | `--border-hairline/strong`                 | 1px `#d9d9de` / `#c7c7cc`（亮）；`#3a3a3c` / `#48484a`（暗） |
| 选中底   | `--surface-selected`                       | 品牌色 8%（亮）/ 16%（暗），或中性 `#e8e8ed` / `#3a3a3c`     |
| 阴影     | `--shadow-1/2/3`                           | 1/2/8px 三级，暗色改用描边 + 更低透明度                      |

> 注意：字号、间距、圆角令牌**必须写在 `@theme` 内**才会生成 `text-*` / `p-*` / `rounded-*` 工具类；写在 `:root` 只会成为普通变量（这正是当前失效的原因）。

### 15.2 组件契约（每个组件必须有）

| 状态          | 要求                                            |
| ------------- | ----------------------------------------------- |
| default       | 边框/底色可辨（≥3:1 与非交互背景）              |
| hover         | 背景或边框变化，150ms                           |
| focus-visible | 2px 环 + 2px offset，且不被祖先裁切             |
| active        | 轻微缩放或压暗                                  |
| disabled      | 降低对比 + `cursor: not-allowed` + 原因 tooltip |
| loading       | 局部 spinner，禁止重复提交                      |
| error         | 语义色 + 图标 + 可重试                          |
| selected      | 与 hover 可区分，≥1.3:1                         |
| empty         | 说明 + 主行动                                   |

### 15.3 状态矩阵（必须逐页补齐）

每页至少定义：`empty`、`loading`、`error`、`partial`、`stale`、`destructive`。

### 15.4 可访问性基线（WCAG 2.1 AA）

- 文本对比 ≥4.5:1（12px 尤其）；UI 边界 ≥3:1。
- 全键盘可达；焦点可见；对话框焦点陷阱与归还。
- 表单标签关联；错误 `aria-describedby`；状态 `aria-live`。
- 颜色不作为唯一信息载体（状态列加文字/图标）。
- `prefers-reduced-motion` 与 `prefers-contrast` 适配。
- 动态 `lang` 属性。

### 15.5 设计系统治理

- CI 校验：源码中使用的类名必须存在于构建产物。
- 禁止组件内硬编码颜色/阴影/字号；ESLint 规则或 Stylelint 自定义规则。
- 设计令牌变更需同时更新亮/暗两套并跑对比度脚本。

const css = fs.readFileSync('out/renderer/assets/index-1_xhN5jD.css', 'utf8')
const files = [](function walk(dir) {
  for (const f of fs.readdirSync(dir, { withFileTypes: true })) {
    const p = path.join(dir, f.name)
    if (f.isDirectory()) walk(p)
    else if (/\.(tsx|ts)$/.test(f.name)) files.push(p)
  }
})('src/renderer/src')

const used = new Set()
for (const file of files) {
  const src = fs.readFileSync(file, 'utf8')
  const re = /className=(?:"([^"]*)"|'([^']*)'|\{`([^`]*)`\})/g
  let m
  while ((m = re.exec(src))) {
    const raw = (m[1] ?? m[2] ?? m[3] ?? '').replace(/\$\{[^}]*\}/g, ' ')
    for (const token of raw.split(/\s+/)) if (token) used.add(token)
  }
}

const escape = t => t.replace(/[:/\[\].%(),#!]/g, c => '\\' + c)
for (const token of used) {
  if (!css.includes('.' + escape(token))) console.log('MISSING', token)
}

### 附录 D：术语

- **令牌（token）**：设计变量的最小单位，如颜色、字号、间距、圆角、阴影。
- **命名空间（namespace）**：Tailwind v4 中决定某类工具类是否生成的令牌前缀，如 `--color-*`、`--spacing-*`、`--text-*`、`--radius-*`。
- **P0/P1/P2/P3**：见 2.3。
- **假虚拟化**：只截断数据量而不做窗口化渲染，DOM 节点数仍与数据量同阶。
